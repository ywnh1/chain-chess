你点下的每一颗棋子，都可能引爆整张棋盘。

**连锁棋** 是基于 Chain Reaction / 爆裂棋玩法改进的多人策略游戏。2~10 人对战，棋子攒满格子就炸，炸出来的棋子接着引爆下一轮，直到分出胜负。

前端和 AI 引擎是同一份代码，出三种形态：**Tauri 桌面（Windows / Linux）/ Android 应用**（Rust 引擎 + Rayon 多核并行），以及**浏览器 PWA**（引擎编译成 WASM，可安装离线游玩）。不依赖服务器，本地就能开局；联机走局域网直连。

## 🎮 游戏规则

- **落子**：点空位长出一颗 1 点的棋子，点自己的棋子加 1 点。首步要避开已有棋子周围 12 格
- **爆裂**：格子攒满阈值就炸，朝上下左右各送点，自己这格清空。阈值可选 3 / 4 / 5 点（默认 4），差 1 点就是临界
- **高阈值双爆**：选 5 级时，会有一个方向多送一份能量 —— 可选「相邻一格送 2 点」或「相邻两格各送 1 点」
- **同化**：炸出的点落到空格 → 长出一颗你的 1 点棋子；落到对方棋子 → 变成你的，点数 +1
- **连锁**：被同化或加点的格子如果到了阈值，立刻跟着炸，一路传到没有格子再够阈值
- **边界**：炸到盘边的点可以消失、从对面回环、反弹，或按形状边缘降级（越靠边越容易爆）
- **胜负**：默认「只剩一人」；也可选「棋子数碾压」或「点数碾压」提前结束

完整规则与策略见 [RULES.md](RULES.md)，或应用内「更多 → 教学」。

## ✨ 功能一览

### 游戏模式

- **本地对战**：2~10 人在同一台设备上轮流落子，每人可自定义名称
- **AI 对战（PVE）**：1 名人类 + 1~9 个 AI，每个 AI 的算法、搜索深度、随机刻度都能单独配
- **AI 斗蛐蛐**：2~10 个 AI 互相对战，纯观赏
- **局域网联机**（桌面 / Android，入口在首页）：
  - 同一 Wi-Fi / 热点下直连，不经过任何服务器，支持 UDP 广播发现房间
  - 房主可选棋盘形状、边界、阈值、双爆方式、胜负判定、局内排名依据，以及**每个 AI 各自的算法**
  - 规则开局前实时同步给所有人，其他玩家只读
  - 房内可混入 AI（0~9 个），AI 由房主那一台设备计算
  - **IPv6 跨网络联机**：默认关闭，在「更多 → 联机」里打开后房间页才显示公网地址（可一键复制）。能否真正连上取决于对方网络、路由器/光猫是否放行 IPv6 入站、以及运营商策略 —— 移动数据通常拦截入站，多数情况需要在路由器里关掉 IPv6 防火墙

### 游戏配置（可存多套预设）

开局页只留棋盘形状与人数，其余规则都在「游戏配置」二级页里：

- **棋盘边界**：默认 / 回环 / 反弹 / 降级 / 随机
- **爆炸阈值**：3 级速爆 / 4 级标准 / 5 级重炮 / 随机
- **双爆方式**（阈值 5/6 时）：相邻一格爆两个 / 相邻两格各爆一个
- **胜负判定**：只剩一人 / 棋子数碾压 / 点数碾压（碾压判定需至少 3 人）
- **局内排名依据**：ML 评分（默认）/ 棋子数 / 点数
- **配置预设**：以上规则可命名保存，最多 20 套随时切换；内置「标准」不可删

### 棋盘与玩家

- **棋盘形状**：正方形 5×5 ~ 19×19、长方形（长宽各 5~19）、随机棋盘（按人数自动生成异形），或用形状编辑器自己点出不规则形状
- **自定义棋盘库**：画好的形状可命名保存（最多 30 块），随时切换、编辑、删除，可导出导入 JSON
- **玩家配置**：每位玩家的类型（人类 / 各类 AI）、名称、算法、搜索深度、随机刻度、评估函数（ML / 手写）

### AI 引擎

- **三种算法**：策略（启发式规则）、Alpha-Beta 剪枝、PVS NegaMax（MCTS 因胜率过低已在游戏内移除）
- **Rust + Rayon**：全部 Rust 实现，桌面端多核并行，深度 1~10 层可配
- **ML 评估**：XGBoost 模型内嵌在引擎里，离线可用；也可切换为纯手写启发式

### 局内排名与场面评分

- **玩家条**：棋盘上方那一排标签，每轮按选定指标重新排序（默认 ML 评分），已淘汰者沉底
- **ML 场面评分**：落子后异步给每位玩家算场面分，不挡落子手感
- **结算图表**：棋子数、点数、ML 评分三条折线（评分图支持负值），前两者可全屏查看
- **最具价值的一步**：列出每位玩家单步评分正增长最大的那一手

### 用户界面

- **液态玻璃主题**：深色虹彩渐变玻璃 UI，10 个彩色光球缓慢浮动（可关闭）
- **背景跟随**：对局中背景随当前玩家色变化（可关闭）
- **响应式布局**：平板横屏、手机竖屏各自适配，挖孔屏安全区处理
- **路由管理**：统一 Router 管理页面，二级页一律「从哪进就回哪」

### 数据与统计

- **历史记录**：自动保存对局，可回看统计图表、回放对局（0.5x / 1x / 2x / 4x 倍速）
- **多选批量管理**：点选择框或长按进入多选，可反选、批量导出、批量删除
- **搜索与筛选**：按玩家名 / AI 算法 / 模式查找，模式筛选含局域网
- **中断恢复**：异常退出或手动暂停时自动存下未完成的对局，历史页一键继续
- **内存 + 磁盘两层存储**：超过 500 步自动溢出到磁盘

### 设备性能检测

- **WebView 性能**：WebGL 压力测试，报告平均 / 最低 / 1% Low FPS、丢帧统计、GPU 信息
- **AI 计算性能**：50 局 AI 对局基准，报告各算法胜率与每局耗时

### 音效与反馈

- **合成音效**：落子、爆炸、淘汰、获胜各有独立音频反馈（Web Audio API），可换主题或导入自定义音频
- **震动反馈**：Android 原生支持，桌面静默降级
- **连锁动画跳过**：长连爆可一键跳过，也可设为自动跳过

```bash
cd tauri
```

## 🤖 AI 引擎详解

三款 AI，分属两种思路：启发式规则、树搜索剪枝。

### ⚡ 策略算法（启发式规则）

Rust 实现，按人工定的优先级出招，不做树搜索，响应最快，适合新手入门和低算力设备。

- **三级优先**：棋子攒到 3 颗就先动它，好触发连锁
- **安全升级**：躲开对手三级棋子旁边的二级棋子，免得被吞
- **渐进控制**：一进二、下三级，逐步扩大地盘

### 🧠 Alpha-Beta 剪枝

标准 Alpha-Beta 剪枝，Rust + Rayon 多核并行。每次走法克隆棋盘而不是撤销，多玩家连锁反应天然适配。

- **Rayon 多线程**：根节点走法并行搜索，吃满多核 CPU
- **走法排序**：三级棋子优先、周围对手多的优先，剪枝更有效
- **根级分支**：根级只搜 top 10 走法，内部节点全量搜索
- **深度可调**：1~10 层（默认 2）

### 🔬 PVS NegaMax（精炼剪枝）

PVS 是 Alpha-Beta 的精炼版：先假设第一个走法最好，后面的用零窗口试探，快速证伪。

- **Killer 启发**：每层记两条杀招走法，后续优先尝试
- **History 启发**：全局历史表记录各位置的成功率
- **QSearch 静止搜索**：搜到底时只搜爆炸性走法，防止水平线效应
- **动态分支控制**：浅层多搜，深层少搜
- **根级 Rayon 并行**

360 局两两对战评测（7×7、正方形与口字棋盘、ML 评估、深度 2、标准 4 点阈值）里，Alpha-Beta 胜率 78.8%，PVS 48.3%，策略 22.9%。A-B 与 PVS 的强弱随棋盘形状和边界变化：正方形 + 默认边界下 PVS 反而更好（66.7%），其余组合 A-B 领先 10~47 个百分点。完整报告在 `tauri/tests/ai_performance_analysis.md` 与应用内「更多 → AI 性能评测」。

### 🤖 评估函数

Alpha-Beta 和 PVS 可以换用两种评估函数：

- **ML 模型**（默认）：XGBoost 树模型打分（18 维特征），再与手写启发式混合；模型内嵌在引擎里，离线可用
- **手写规则**：纯启发式评估，计算量小，设备弱时更流畅

在玩家配置弹窗里随时切换，不用重启游戏。局内排名的 ML 评分也用同一个模型。

## 🔧 技术架构

```
┌──────────────────┐       ┌─────────────────┐
│   Web 前端（JS） │       │    Rust 引擎    │
│                  │       │                 │
│  ┌─ UI 渲染 ──┐  │       │  ┌─ AI 搜索 ──┐ │
│  │ 棋盘/弹窗/ │  │       │  │  A-B/PVS   │ │
│  │ 图表/路由  │  │       │  └────────────┘ │
│  └────────────┘  │       │  ┌─ 评估函数 ─┐ │
│  ┌─── 音效 ───┐  │◄─────►│  │  ML/手写   │ │
│  │ Web Audio  │  │invoke │  └────────────┘ │
│  └────────────┘  │       │  ┌─ 游戏逻辑 ─┐ │
│  ┌── 存储 ────┐  │       │  │ 落子/连锁/ │ │
│  │  Tauri FS  │  │       │  │  胜负判定  │ │
│  └────────────┘  │       │  └────────────┘ │
└──────────────────┘       └─────────────────┘
```

- **前端**：原生 JavaScript + CSS，零框架依赖（`tauri/public/`，桌面与移动端共用）
- **共享引擎**：`engine/`（crate `chain_chess_core`）放规则、AI 搜索、评估与内嵌模型，两个宿主共用同一份代码
- **桌面（Windows / Linux）/ Android**：Tauri v2 宿主（`tauri/src-tauri/`），Rayon 多核并行；局域网联机在 `lan.rs`（TCP 双栈监听 + UDP 广播发现）
- **浏览器 PWA**：`docs/wasm/` 只留 wasm-bindgen 导出层，依赖 `engine/` 编成 WASM；`engine.js` 在浏览器侧模拟 Tauri invoke 语义，`tauriInvoke` 自动降级到 `ChainEngine.webInvoke`
- **AI 引擎**：Alpha-Beta 用 `alpha_beta_pruning` crate，PVS 与策略算法自己实现
- **并行计算**：Rayon `par_iter()` 多核并行搜索（桌面端；WASM 版单线程顺序执行）
- **存储**：桌面和移动端用 JSON 文件（`history.json`、`round_data.json`、`saved_game.json`），PWA 用 `localStorage`（`chainchess:` 前缀）

更细的 PWA 说明见 [docs/README.md](docs/README.md)。
