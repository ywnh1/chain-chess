Tauri 与技术栈

这些是连锁棋在性能上做的事，下面两项检测会实测它们在你这台设备上的效果：

  • Tauri 2：Rust 内核 + 系统 WebView，比 Electron 省内存，启动也快
  • Rust 引擎：游戏规则和 AI 全用 Rust 写，编译成原生码；PWA 版编译为 WASM
  • Rayon 多核并行：A-B / PVS / MCTS 在根节点并行搜索，多核 CPU 都吃得上
  • 搜索剪枝：Alpha-Beta 剪枝、PVS 主变例搜索（Killer / History / 静止搜索）、MCTS
  • ML 评估：内置 XGBoost 模型（18 维特征），AI 判断更准
  • WebGL 渲染：棋盘用 Canvas 画，动画批量提交，渲染压力交给 GPU

为什么玩连锁棋

你点下的每一颗棋子，都可能引爆整张棋盘。本地热座、人机对战、AI 斗蛐蛐，2~10 人同台。桌面 / Android / 浏览器 PWA 三端都能跑，不用服务器，打开就能开局。

游戏规则

往格子里堆自己的棋子。堆满一格就会炸，炸出去的棋子推着旁边的格子接着炸，最后一个还有棋子的玩家赢。

  1. 下子：点空格放一颗自己的棋子；点自己已经有棋子的格子，再添一颗。别人的格子点不动。
  2. 爆炸：攒够 4 颗就炸，朝上下左右各弹一颗。弹出去的棋子算你的。
  3. 连锁：弹出去的棋子落进旁边的格子，那格要是也堆到 4 颗，跟着炸。一路炸到没格子再够 4 颗为止。
  4. 出局：你在棋盘上的棋子被炸光，就出局了。
  5. 获胜：最后还有棋子留在棋盘上的人赢。
  6. 第一手：不能下在已有棋子周围那 12 格里（上下左右各 2 格，加四个斜角），省得一开局就贴着打。
  7. 第一颗棋子：落下就是“差一颗要爆”的状态，4 级规则下算 3 颗。所以抢地盘那一步常常直接炸开。

第一次玩就选 2 人、7×7、默认边界、4 级，以后想换再换。每项设置后面的「!」会告诉你它影响什么。

AI 介绍

连锁棋有 四种 AI，思路分三类：按人工规则下、搜索推演、随机模拟。本地对战、AI 对战、AI 斗蛐蛐里都能随便换。四种都用 Rust 引擎实现，桌面端 A-B/PVS/MCTS 走 Rayon 多核并行，PWA 版是单线程 WASM。

策略算法 · 启发式规则

不做搜索，按人工排好的优先级直接出招，所以最快，新手和低配设备都用得上。

三级优先 → 优先走即将爆裂的棋子（count=3）
安全升级 → 避开对手三级附近的二级棋子
渐进控制 → 一进二、下三级，逐步扩大地盘
首子中心 → 第一手落子在棋盘中央附近

Alpha-Beta 剪枝 · 经典搜索

标准的 Alpha-Beta 剪枝，Rust + Rayon 在根节点并行。走法是复制棋盘而不是撤销，多玩家连锁反应下反而更省事。

搜索深度 1~10 层 · 根级分支 top 10 · 走法排序 三级优先
随机化探索 早期对局加入随机扰动，增加走法多样性
评估函数 支持增强版（位置+威胁评分）或手写规则评估

PVS NegaMax · 精炼剪枝

Principal Variation Search（主变例搜索）：先假定最优走法排在第一，后面的走法用零窗口（Null Window）快试一下，要么马上证明它不如第一位，要么重搜。432 局两两对战里（ML 评估 · 深度 2），PVS 拿到 71.3%，紧追 A-B 的 73.6%，详见「AI 性能评测」。

Killer 启发 每层记录两条杀招走法 · History 启发 全局走法成功率表
QSearch 静止搜索 到底层只搜索爆炸性走法（限3层），消除水平线效应
动态分支 浅层多搜深层少搜 · 根级 Rayon 并行 多核加速

MCTS 蒙特卡洛树搜索 · 随机模拟

不用评估函数，也不猜哪步好，直接随机模拟大量对局（单次最多 40 步，分出胜负就停），靠胜率统计决定走哪步。

SELECT → EXPAND → PLAYOUT → BACKPROPAGATE
UCB1 平衡探索与利用 · 随机 Playout（均匀随机模拟）· 渐进展开（≥3 次访问才展新分支）

depth=1~10 对应 400~4000 次迭代，树节点上限 2000。不靠评估函数的好处是，常能找出 Alpha-Beta 看不到的路子。

AI 性能评测

两两对战 AI 实力测试（432 局）

6 配对（全两两）× 4 边界 × 3 爆炸阈值 = 12 模式 · 每模式 6 局（先手轮换，消除先后手偏差）
7×7 棋盘 · A-B / PVS 深度 2 · MCTS 深度 1 · ML 评估 · 首子合法分散布局 · 随机刻度 0
测试脚本: tauri/src-tauri/src/bin/strength_test.rs（Rust 端引擎）

总结

  • 搜索算法领先：A-B 73.6%，PVS 71.3%。策略和 MCTS 加起来只有 119 胜（A-B 159 胜 / PVS 154 胜）
  • 策略算法中间偏上（46.8%）：速爆 3 的低阈值下它最能打，对 A-B 拿到 4:2，对 PVS 打出过 3:3 和 5:1。“临界引爆”的直觉跟搜索结果很接近
  • MCTS 垫底（8.3%）：深度 1 在 7×7 上模拟量不够（根分支约 400 次迭代），平均 103 步就结束，多数是快速送死。想提强度得加迭代量
  • 阈值决定强弱分界：cap4 标准模式下搜索算法几乎全取（大量 6:0 / 0:6），cap3 下策略算法反过来能咬下几局
  • 边界影响节奏：回环（wrap）最快，部分模式平均 45~92 步；反弹和降级容易打成长链僵持，平均能到 361~448 步
  • 432 局没有平局，先手也没占到便宜：各配对的先手胜率都在 50% 上下，先手轮换这个设计是有效的

关键洞察

  • 为什么 A-B / PVS 领先？ 搜索算法能推演 2 层连锁爆炸和淘汰，启发式只做单步贪心。cap4 / cap5 下多步连锁的价值很大，搜索赚得最多
  • cap3 下策略为什么能抗衡？ 阈值低的时候棋盘上“临界棋子”密集，每一步都是爆炸点，深搜和浅贪心得出的结论差不多，启发式规则正好戳中
  • MCTS 均步最短（103.4），说明它常在中期就崩掉，而不是打满长局。加迭代量（depth 2~3）或换 UCT 变体是后面可以试的方向
  • 回环边界更快，因为爆炸能量绕圈回流，清盘快；反弹和降级会造出“打不死”的僵持局
  • ML 评估确实起作用：这次用的是新训练的 18 维阈值感知模型（800 树），A-B / PVS 在高价值长局里能认出爆发链

第三方 SDK 与服务

数据放在哪

连锁棋没有账号系统，也不需要登录。棋盘、走法、对局记录全部保存在你自己的设备上，不会上传到任何服务器。应用只在两处会访问网络：访问量统计与版本更新检查。

会联网的第三方服务

  • 51.la 站点统计 SDK第三方统计SDK 地址 sdk.51.la/js-sdk-pro.min.js · 页面加载时引入并自动初始化（autoTrack）。用来统计访问量（PV/UV）、访问来源和大致设备环境，看有多少人在玩。它不会读取或上传棋盘、走法、对局记录、玩家名称等任何游戏内容。脚本加载失败（断网、被插件拦截）时游戏功能不受影响。桌面 / Android 应用使用与网页版相同的页面，因此也会引入该脚本。
  • Gitee 仓库接口更新检查接口地址 gitee.com/api/v5/repos/ywnh1/chain-chess-release/contents/update.json · 启动时静默请求一次，或在设置里点「检查更新」时请求。只读取公开仓库里的版本号文件，用来判断有没有新版本；不发送账号、设备标识或游戏数据（请求本身的 IP 与 User-Agent 由 HTTP 协议附带，代码未额外附加任何信息）。

除了这两个域名，应用不会主动请求别的地方。

系统能力（Tauri 插件）

  • tauri-plugin-dialog本地导出历史记录时弹出系统的「保存文件」对话框。
  • tauri-plugin-fs本地把导出的历史记录 JSON 写入你选定的位置，启动时读取本机历史记录文件。
  • tauri-plugin-opener本地用系统默认方式打开下载页面或已下载的安装文件。

三个插件都只在本地工作，不联网，也不会在你没操作的时候读写文件。

本应用不包含

无广告 SDK、无账号 / 登录 / 支付 SDK、无崩溃上报 SDK、无社交分享 SDK、无用户画像或行为分析 SDK（访问量统计仅由上面的 51.la 提供）。

不想被统计怎么办

网页版可以用浏览器的隐私扩展或广告拦截规则屏蔽 sdk.51.la 域名，屏蔽后所有游戏功能照常可用；彻底断开网络也能正常游玩（只有「检查更新」会失败）。

开源库的许可证清单见「关于 → 许可证」页，完整源码以 MIT 协议公开在 GitHub。
